## 1. Overview

**Observed:** The main weapon upgrades from +0 through +15. The forge must be built, and attempts consume gold, iron and enhancement stones. Protection is an optional toggle that consumes one protection stone on **every attempt**, including success. User decision: **preserve current enhancement rules**, not redesign them in this documentation pass. This is an instruction to retain existing behavior, not approval of every balancing constant.

## 2. Detailed Design

- Browser `enhancePreview()` reads five 15-element level-indexed arrays. `attemptEnhancement()` refuses max level, missing forge or missing resources; otherwise spends resources before rolling.
- Success increments enhancement level, updates historical maximum and resets the failure count for the attempted level.
- Failure increments that level's counter; from +5 onward, an unprotected failure reduces the current level by one. Protection prevents the downgrade but does not refund materials.
- Pity: when the attempted level's stored failures reach `pityCap[level]-1`, the next attempt is guaranteed; caps are absent for levels +0–+4, 10 at +5–+8, 15 at +9–+11 and 20 at +12–+14.
- Pure module `src/rules/enhancement.cjs` exports `validateRules`, `attackBonus`, `getRule`, `validateAttempt`, `getPreview`, `executeAttempt`; the browser currently implements the same policy separately rather than importing this module.
- `highestEnhancementLevel` is historical and does not block downgrade. `failuresByLevel` persists separately for each level, including when the weapon downgrades.
- Inventory stores enhancement/protection/awakening/evolution stones and ancient wood; only enhancement and protection stones participate in this upgrade attempt.

## 3. Formulas Discovered

| Rule | Observed expression |
|---|---|
| Total attack | `p.atk + 4*n + floor(n**1.6)` where `n` is current enhancement level |
| Success | `guaranteed || random() < chance[n]` |
| Pity | `pityCap[n] !== null && failuresByLevel[n] >= pityCap[n]-1` |
| Failure downgrade | `n >= 5 && !protectEnhancement ? n-1 : n` |
| Success probabilities | `[100,95,90,85,75,65,55,45,35,25,18,12,8,5,3]%` for attempts from +0 through +14 |
| Gold cost | `[50,80,120,200,300,500,700,900,1200,1500,2000,2600,3500,4500,6000]` |
| Iron cost | `[1,2,3,4,6,8,10,12,15,18,22,28,35,45,55]` |
| Enhancement stone cost | `[1,1,1,2,2,3,4,5,6,7,9,11,14,18,25]` |

All arrays are indexed by **current level**; +5 to +6 uses index 5.

## 4. Edge Cases and Dependencies

**Handled:** +15 rejects attempts; missing forge/materials rejects without spending; protected failure does not downgrade; guaranteed attempts skip RNG in pure module; invalid rule arrays are rejected in pure module.

**Risks:** browser `game.js` has no equivalent full validation of malformed live state; two independent implementations can drift. Browser state uses `p.gold`/`p.iron` while pure module expects those fields inside `inventory`. A refactor must adapt the state shape explicitly. Existing game saves after an attempt; storage failure sets a warning.

**Dependencies:** forge construction; resource inventory and mining; combat attack calculation; save v3; HUD preview; reward pity (different counters from enhancement-failure pity).
