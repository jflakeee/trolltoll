## 1. Overview

The browser stores player position, stats, equipment flags, resources, boss clears and progression in `localStorage`. The primary key is `trolltoll_web_v3`; a legacy mirror is written to `trolltoll_web_v2`. On startup, a structurally valid v3 record takes precedence, otherwise the game falls back to v2 or v1. The separate pure module implements stricter normalization/migration and is not invoked by the browser runtime.

## 2. Detailed Design

- Browser load: parse v3; require `schemaVersion===3` and an object `legacy`. If invalid or unavailable, load v2/v1. If parsing throws, retry legacy and ultimately initialize defaults.
- `p` holds live legacy fields including position, level, XP, base attack/defense, HP, kill count, materials, equipment/facilities and boss IDs. `progression` holds inventory, weapon enhancement and reward pity.
- Browser save writes v3 `{schemaVersion:3,revision:0,legacy,progression}` and then the v2 legacy mirror. No transactional/atomic write spans the two keys.
- Save triggers: every 5 seconds, `pagehide`, document hidden, enemy kill, gather completion, craft/build actions and enhancement attempts.
- Browser errors in save set `storageWarning=true`; `SecurityError`/`QuotaExceededError` on load also trigger the warning.
- Pure module `migrateSave` supports schema 1, 2, 3 and no-version legacy objects; it sanitizes nonnegative integer counters, boss IDs, equipment levels 0–15 and failure-counter keys 0–14. `decodeSave`/`encodeSave` are JSON adapters.

## 4. Edge Cases and Dependencies

**Handled:** absent data defaults; v3 with invalid legacy structure falls back; browser clamps invalid enhancement counters and boss IDs; pure module rejects unsupported schema versions and invalid v3 legacy structures.

**Risks:** browser loader does not call `migrateSave` and may interpret a malformed but structurally valid v3 differently from the pure module. A valid JSON v3 with `legacy` object can bypass stricter normalization. Writes to v3 and v2 are non-atomic, and v2 cannot preserve enhancement/progression inventory. Browser saves do not use `revision` to detect stale data.

**Dependencies:** all persistent gameplay systems; browser storage availability; versioned state contracts. **INTENT UNKNOWN:** Should corrupt v3 automatically fall back to v2, or surface recovery options? Is the v2 mirror intended for long-term compatibility?
